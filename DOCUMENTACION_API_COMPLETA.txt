🔑 SISTEMA DE ROLES Y PERMISOS
===============================================================================

ROLES DISPONIBLES:
├── OWNER: Dueño de barbería (acceso total a su empresa)
├── EMPLOYEE: Empleado (acceso limitado)
├── CLIENT: Cliente (solo reservas propias)
└── ADMIN: Administrador del sistema (acceso global)

ENUM PublicoObjetivo:
├── HOMBRES
├── MUJERES
└── MIXTO

ESTADOS DE RESERVA:
├── PENDING: Pendiente
├── CONFIRMED: Confirmada
├── COMPLETED: Completada
└── CANCELLED: Cancelada

TIPOS DE DESCUENTO:
├── PORCENTAJE: Descuento en porcentaje (1-100%)
└── MONTO_FIJO: Descuento en monto fijo

===============================================================================
🌐 FLUJO DE AUTENTICACIÓN
===============================================================================

1. Login → POST /api/auth/login → Recibe JWT token
2. Header Authorization: Bearer {token}
3. Token expira en 24 horas
4. Verificación de email requerida para activar cuenta

Ejemplo de uso:
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

===============================================================================
📱 FLUJO DE REGISTRO
===============================================================================

PARA EMPRESA:
1. POST /api/registro/empresa
2. Se envía email de verificación
3. Usuario verifica con /api/registro/verify?token=... o /api/registro/verify-code
4. Cuenta activa para login

PARA CLIENTE:
1. POST /api/registro/cliente
2. Verificación de email
3. Login disponible

PARA EMPLEADO:
1. OWNER registra empleado con POST /api/registro/empleado
2. Se envía email de verificación al empleado
3. Empleado verifica su email
4. Login disponible

⚠️ NOTAS IMPORTANTES
===============================================================================

1. SOFT DELETE: Los registros se marcan como eliminados, no se borran físicamente

2. MULTIPART: Servicios y configuración de empresa usan multipart para imágenes
   - Campo de datos: JSON string
   - Campo de imagen: archivo

3. VALIDACIONES: Todas las entradas tienen validaciones estrictas
   - Emails válidos
   - Contraseñas seguras (@ValidPassword)
   - Longitudes de campos

4. PAGINACIÓN: Disponible en endpoints que manejan listas grandes
   - Parámetros: page, size, sort
   - Ejemplo: ?page=0&size=10&sort=nombre

5. PRINCIPAL: Los controladores usan Principal principal para obtener el usuario autenticado

6. FECHAS: Formato ISO 8601 (yyyy-MM-ddTHH:mm:ss)
   - Ejemplo: 2024-12-25T14:30:00

7. ZONA HORARIA: El sistema maneja fechas en la zona horaria local del servidor

8. ARCHIVOS: Supabase storage para logos, banners e imágenes de servicios

9. EMAIL: Sistema de verificación por email con códigos de 6 dígitos

10. SEGURIDAD: BCrypt para hash de contraseñas, JWT para autenticación
